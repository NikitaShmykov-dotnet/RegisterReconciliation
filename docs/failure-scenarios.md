# Сбои и гонки

HTTP-сценарии с плохими строками, отсутствующим ключом и повторным решением проверяет `./scripts/demo.ps1` на запущенном сервисе.

| Сценарий | Наблюдаемый результат |
| --- | --- |
| Повреждённые строки с допустимым заголовком | Пакет содержит отчёт ошибок. `POST /runs` возвращает `422` для этого пакета. |
| Повреждённый заголовок, UTF-8 или NUL | `400`, пакет целиком отклонён. |
| Тело больше 32 МиБ | `413`. Лимит применяется и к запросам без Content-Length. |
| Ключ отсутствует или роль не подходит | `401` без действительного ключа, `403` с ключом другой роли. |
| Пока идёт импорт, поступает запрос на сверку | `429` без очереди. Отмена первого запроса освобождает слот после завершения отката. |
| Параллельные идентичные импорты | Один новый пакет, остальные получают ссылку на него. |
| Ошибка PostgreSQL при публикации импорта или результатов | Транзакция откатывается целиком. После снятия ограничения запрос можно повторить. |
| Два проверяющих одновременно сохраняют решение | Одно решение в БД, проигравший запрос получает `409`. |
| Нет соединения с PostgreSQL после старта | `/health/ready` возвращает `503`. Незавершившиеся записи откатываются PostgreSQL. |

Команда для транзакционных сценариев:

```powershell
dotnet test -c Release --filter FullyQualifiedName~PostgresTests
```

Тесты в отдельных схемах добавляют ограничение, которое отклоняет конкретную строку при публикации или COPY. Затем проверяют отсутствие частичного результата, снимают ограничение и повторяют запрос. При заданной `RECONCILE_TEST_POSTGRES` они работают на указанной PostgreSQL, иначе поднимают контейнер.

`dotnet test -c Release --filter FullyQualifiedName~HttpTests` проверяет HTTP-маршруты с PostgreSQL. Тест лимита блокирует импорт на уровне БД, проверяет отказ следующей сверки и отменяет импорт, затем проверяет, что слот снова доступен.
