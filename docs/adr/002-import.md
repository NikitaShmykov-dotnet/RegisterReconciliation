# Идентичный импорт

Ключ импорта — источник и SHA-256 исходных байтов. BOM, переносы строк и пробелы участвуют в хеше. Совпадение по смыслу при изменённых байтах образует новый пакет. Два источника могут сохранить одинаковый файл независимо.

Уникальный ключ резервируется в начале транзакции. Победитель пишет строки и ошибки через бинарный COPY во временную staging-таблицу. Публикация и обновление счётчиков входят в ту же транзакцию. Конкурентный запрос ждёт снятия блокировки ключа. Если первый импорт завершился, повтор получает готовый пакет, при откате может сам его опубликовать.

Здесь используется Npgsql напрямую. COPY и уникальный ключ с `ON CONFLICT` покрывают основной сценарий без отдельной модели EF для staging.
