# Локальная проверка

8 ноября 2026 г., Windows 11 Pro 23H2 (22631), Intel Core i7-8750H, 6 ядер и 12 потоков, 32 ГиБ ОЗУ. SDK .NET 10.0.403, PostgreSQL 18.6 на той же машине. Проверки выполнены из каталога проекта. SDK был распакован в `.local`, поэтому вместо `dotnet` использовался `./.local/dotnet.exe`.

| Команда | Результат |
| --- | --- |
| `dotnet restore` | Пакеты восстановлены. |
| `dotnet build -c Release --no-restore` | 0 ошибок и предупреждений. |
| `dotnet test -c Release` | 17 пройдено, 0 пропущено. `RECONCILE_TEST_POSTGRES` указывала на отдельный локальный экземпляр PostgreSQL. |
| `dotnet format --no-restore --verify-no-changes` | Код возврата 0. |
| `./scripts/demo.ps1` с ключами оператора и проверяющего | Две ошибки CSV, все шесть категорий, одинаковые результаты повторной сверки, решение и экранированный экспорт. Приложение стартовало на базе, созданной до переименования проекта. |

SQL-тесты покрывают восемь параллельных импортов, два параллельных решения и откаты при ошибках записи. HTTP-тесты покрывают роли, лимиты, ошибки импорта, пагинацию, аудит и экспорт. Тест отмены проверяет, что зависший на блокировке PostgreSQL импорт освобождает слот, а незавершённый пакет откатывается.

Демон Docker был недоступен при исходной проверке. Контейнерные запуски Compose и Testcontainers пока не проверены. Для контейнерной проверки запустите Docker, выполните команды запуска из README, затем уберите `RECONCILE_TEST_POSTGRES` из окружения и запустите тесты. Workflow подготовлен как шаблон.

## 100 000 строк

Сборка Release, один последовательный прогон через HTTP, пустая база PostgreSQL, новый процесс API. Два файла по 50 000 строк, вместе 5 155 688 байт. В каждом файле 25 000 точных ID, 20 000 строк для пар по сумме, валюте, заказу и времени и 5 000 строк с одним общим ключом. Последняя группа даёт 10 000 неоднозначных результатов.

```powershell
dotnet build -c Release
$env:ConnectionStrings__RegisterReconciliation = '<строка подключения к пустой базе>'
$env:Operators__ivan = [guid]::NewGuid().ToString('N')
./scripts/measure.ps1
```

С локально распакованным SDK команда измерения была `./scripts/measure.ps1 -Dotnet (Resolve-Path .local/dotnet.exe).Path`. Скрипт измеряет HTTP-время до получения ответа, включая запись в БД. Генерация входа и запуск приложения вынесены за пределы замера.

| Показатель | Результат |
| --- | ---: |
| Импорт обоих файлов | 8 569 мс |
| Сверка и запись результатов | 5 371 мс |
| Пиковый рабочий набор процесса API | 150,4 МиБ |
| Совпадения | 45 000 |
| Неоднозначные результаты | 10 000 |

Рабочий набор снят из `Process.PeakWorkingSet64` после сверки и включает запуск API. Память PostgreSQL и процесса PowerShell не учитывалась. Экспорт в этот прогон не входил.

## Конкурентные запросы на максимуме строк

Команда для отдельной пустой базы: `./scripts/measure.ps1 -ConcurrentMax`. Два файла по 150 000 строк, всего 49 260 691 байт. Скрипт отправляет три серии по четыре параллельных запроса: импорт внутреннего файла, импорт внешнего файла и сверку. В каждой серии один запрос получил `201`, три получили `429`.
