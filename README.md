# RegisterReconciliation

Сервис сверяет два неизменяемых CSV-реестра: внутренний и полученный от провайдера. Он показывает расхождения, сохраняет решения проверяющих и выгружает отчёт. В демо все операции вымышлены.

## Запуск

Нужны .NET SDK 10.0.403, PostgreSQL 18 и PowerShell 7 для скриптов. С Docker Compose можно поднять базу из каталога `ReconcileKit`:

```powershell
$env:RECONCILE_DB_PASSWORD = [guid]::NewGuid().ToString('N')
docker compose up -d --wait
$env:ConnectionStrings__RegisterReconciliation = "Host=127.0.0.1;Port=55432;Database=reconcile;Username=reconcile;Password=$env:RECONCILE_DB_PASSWORD"
$env:Operators__ivan = [guid]::NewGuid().ToString('N')
$env:Reviewers__olga = [guid]::NewGuid().ToString('N')
dotnet run --project src/RegisterReconciliation
```

Пароль относится к первичной инициализации тома PostgreSQL. Для повторного запуска с тем же томом используйте прежнее значение. С существующей PostgreSQL достаточно задать строку подключения к отдельной пустой базе. Приложение применяет встроенные SQL-миграции при старте. Для запуска из IDE откройте `RegisterReconciliation.slnx`, выберите профиль `RegisterReconciliation` и задайте те же переменные окружения в конфигурации запуска.

API слушает `http://127.0.0.1:5084`. OpenAPI доступен по `/openapi/v1.json`, состояние базы проверяет `/health/ready`.

## От импорта до отчёта

Во втором терминале задайте те же значения `Operators__ivan` и `Reviewers__olga`, затем выполните:

```powershell
./scripts/demo.ps1
```

Скрипт показывает две ошибки в исходном CSV, получает `422` при попытке сверить этот пакет, затем импортирует корректные файлы из `demo/`. В двух запусках он проверяет одинаковые результаты, записывает решение по неоднозначной строке и сохраняет CSV в `.local/demo-report.csv`. [Шаги и ожидаемые результаты](docs/demo.md).

## Формат входа

Тело запроса `POST /imports/internal` или `POST /imports/external` передаётся как `text/csv`. Заголовок и порядок полей фиксированы:

```csv
external_id,amount,currency,occurred_at,order_reference
provider-7,12.50,USD,2026-01-15T13:00:00+03:00,"order, ""seven"""
```

| Поле | Допустимое значение |
| --- | --- |
| `external_id` | Пустое поле или до 64 ASCII-символов. Первый символ — буква или цифра, далее также допустимы `._:-`. Регистр значим. |
| `amount` | Знаковое десятичное число с точкой, до 16 цифр до точки и до 2 после неё. Знак необязателен. |
| `currency` | Три заглавные латинские буквы. Проверяется формат кода. |
| `occurred_at` | Дата и время с секундами и явным смещением `Z` или `±HH:mm`. До микросекунды, хранится в UTC. |
| `order_reference` | От 1 до 128 UTF-16 единиц без крайних пробелов. Сравнение с учётом регистра. |

Файл в UTF-8 с необязательным BOM, разделитель — запятая. Одна запись занимает одну физическую строку. Запятая и кавычки внутри полей поддерживаются, переносы строк внутри входных полей запрещены. Предел на файл — 32 МиБ и 150 000 записей, на корректную запись — 4096 UTF-16 единиц. Исходный текст сохраняется без разделителя строк. Неверная кодировка, NUL или неверный заголовок отклоняют файл целиком. Остальные ошибки строк остаются в отчёте и блокируют сверку пакета.

## API и границы

| Запрос | Результат |
| --- | --- |
| `POST /imports/{source}` | Новый пакет (`201`) или повтор точных байтов для того же источника (`200`). |
| `GET /imports/{id}/errors?after=0&limit=50` | Ошибки с номерами и исходным текстом. |
| `POST /runs` | Новый запуск для `{"internalBatchId":1,"externalBatchId":2}`. |
| `GET /runs/{id}` | Версия алгоритма и счётчики. |
| `GET /runs/{id}/results?after=0&limit=50` | Пары, расхождения и решения. Следующая страница начинается после `nextAfter`. |
| `POST /runs/{id}/results/{position}/resolution` | Закрытие расхождения с обоснованием, например `{"comment":"Провайдер подтвердил повтор выгрузки"}`. |
| `GET /runs/{id}/export` | CSV со всеми результатами запуска и сохранёнными решениями. |

Ручное решение закрывает отдельное расхождение с комментарием. Исходная категория остаётся видимой, при решении новые пары не создаются. Точное совпадение ID с расхождением суммы или валюты получает категорию `amount-mismatch`. [Правила сопоставления](docs/adr/001-matching.md).

Маршруты реестров принимают ключ в заголовке `X-Api-Key`. Операторы (`Operators__<имя>`) могут читать данные, импортировать файлы и запускать сверку. Проверяющие (`Reviewers__<имя>`) могут читать данные и закрывать расхождения. Отсутствующий или неверный ключ даёт `401`, неподходящая роль — `403`. Используйте отдельные ключи от 16 символов для каждого аккаунта. Это локальная аутентификация для демо.

На экземпляр API одновременно допускается один импорт, одна сверка или один экспорт из общей группы. При занятом слоте следующий тяжёлый запрос получает `429` без ожидания. Загрузка буферизует файл для расчёта SHA-256, а сверка держит в памяти нормализованные операции двух пакетов. При нескольких экземплярах каждый применяет лимит отдельно.

## Проверка

```powershell
dotnet restore
dotnet build -c Release --no-restore
dotnet test -c Release --no-build
dotnet format --no-restore --verify-no-changes
```

Интеграционные тесты по умолчанию запускают PostgreSQL через Testcontainers. Для локальной PostgreSQL задайте `RECONCILE_TEST_POSTGRES` со строкой подключения к тестовой базе. Тестовый пользователь должен иметь право создавать схемы. Для CI скопируйте `ReconcileKit/ci/reconcilekit.yml` из корня репозитория в `.github/workflows/reconcilekit.yml`. В проекте хранится только шаблон.
